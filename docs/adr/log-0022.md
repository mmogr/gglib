Decision 3 holds at the new pin.

**Kill criterion 1, read.** The reading used Llama 3.2 3B Q8_0 on a raw
`b11429` server with `--slot-save-path`, and no request sent `cache_prompt`.

1. On a fresh server, the second identical request reported
   `usage.prompt_tokens_details.cached_tokens` 585 of 586.
2. Slot 0 was saved (587 tokens), the server was restarted, and the slot was
   restored.
3. The same request then reported `cached_tokens` 585 of 586.

The default holds: the prompt was reused after the restore.

`/slots[0].n_prompt_tokens_cache` read 0 after both of those requests. A slot
that finishes a task runs `reset()`, which sets `stats = {}`
(`tools/server/server-context.cpp:404`), and `/slots` reports the previous
task with the zeroed stats (`:734-740`). Read after a request, the criterion's
`/slots` reading is therefore 0 whether or not the prompt was reused, and as
worded it would reverse decision 1 on every reading. Its usable forms are
`usage.prompt_tokens_details.cached_tokens` (or `timings.cache_n`) on the
response, or `/slots` read while the slot is processing. The criterion's
wording is the owner's to change; decision 1 is unchanged. This was not
checked at `972b5fc`.
