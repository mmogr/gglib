## 2026-09-26: both binaries inherit the workspace lints

Finding 1 describes the crates' lint tables as they stood when this ADR was
accepted. The change that made every workspace member inherit
`[workspace.lints]`, whose grandfathered allows #1157 tracks, replaced the
tables of `crates/gglib-cli` and `src-tauri` with `[lints] workspace = true`:

- `crates/gglib-cli/Cargo.toml` no longer re-declares `unsafe_code = "deny"`.
  The CLI inherits it from `[workspace.lints.rust]`.
- `src-tauri/Cargo.toml` no longer declares its own `[lints.rust]`, so
  `gglib-app` is under `unsafe_code = "deny"` as well. An `AttachConsole` call
  there would need an `allow(unsafe_code)` exemption, as `mod layer_shell;` in
  `src-tauri/src/tray/mod.rs` has.

The finding's statement that `gglib-app` "is not under the deny at all" no
longer holds. The `windows_subsystem = "windows"` attribute in
`src-tauri/src/main.rs`, on which the finding rests, is unchanged.
