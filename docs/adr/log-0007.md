## 2026-11-14: tools on a template that calls none, at b12110

`make record-upstream` launches tinygemma3 on its own template and asks it
the recorder's one-tool question (`engine_contract_gemma.rs`). The template's
caps say `supports_tool_calls: false` and `supports_tools: false`. Under
`tool_choice` `auto` and `required` alike llama-server answers 200, the
message carries no `tool_calls`, and the prompt has as many tokens as the
question without tools, so the tools were not rendered
(`contracts/upstream/llama/observed.json`, `toolless.tinygemma3.*`). This is
the source's branch: the tool parser is built only when
`supports_tool_calls` is true (`common/chat-auto-parser-generator.cpp:126` at
`cd959bae9`), and otherwise the reply is parsed as content.

From this change the stored tool flag takes `supports_tool_calls` when it is
first read and when it changes, and library step 10 applied each launched
model's stored answer once. The drop of `tools` for a model whose flag is off
(stage 2b) stays: on such a template it changes nothing the model sees, and
`request_pipeline/measure.rs` measures the whole body, `tools` included, so
the drop keeps unrendered schemas out of the truncation budget. It also keeps
the owner's off meaning off for every client.
