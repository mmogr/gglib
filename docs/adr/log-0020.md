## 2026-10-15: criterion 1 read on the pin, and the template keeps reasoning on both builds

The pin moved from `b10327` to `b11429` (`d81235049`). The models were read
with raw llama-servers (`--jinja -c 8192 -ngl 99`) on one Apple M4 Max. Each
row reads `/props` `chat_template_caps` and renders a three-message history
through `/apply-template`, where the earlier assistant turn carries a
`reasoning_content` marker.

| model | build | `supports_preserve_reasoning` | marker rendered | with `preserve_reasoning: false` |
|---|---|---|---|---|
| Qwen3.8-27B Q8_0 | `b11429` | true | yes | no |
| Qwen3.8-27B Q8_0 | `b10327` | true | yes | no |
| Qwen3.5-4B Q8_0 | `b11429` | false | no | no |
| Qwen3.5-4B Q8_0 | `b10327` | false | no | no |

- **Criterion 1** holds on the pin: Qwen3.8-27B records `true`. Qwen3.5-4B
  is read for the first time, and records `false`.
- **The server-wide default.** The Context's "llama-server binds it true by
  default" is true only from `b11429`, which sets `preserve_reasoning` to
  `"true"` unless it is given (`common/arg.cpp:964-966` at `b11429`).
  `b10327` set it only on `--reasoning-preserve`.
- **Qwen3.8 is not affected.** Its template keeps earlier reasoning when the
  variable is unset (`preserve_thinking is undefined or preserve_thinking is
  true`), so the marker rendered at `b10327` too. The new default changes
  what is rendered only for a template that keeps reasoning when the
  variable is set, and drops it when it is not.
- Criteria 2 and 3 were not read.
