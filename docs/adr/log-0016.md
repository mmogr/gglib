## 2026-10-15: the kill criterion's second reading, taken at the b11429 bump

Taken when `PINNED_LLAMA_RELEASE` moved to `b11429`, as the criterion says.

**Setup.** A raw `b11429` llama-server on one Apple M4 Max, running
`Qwen3.5-4B-Q8_0.gguf` with `--mmproj mmproj-F16.gguf` (unsloth), `--jinja -c
8192`. `/props` reports `vision: true`.

**Request.** One chat completion at temperature 0: a user message asking what
colours the picture shows, an assistant `get_image` call, and a `role:
"tool"` message carrying a text part and an `image_url` part. The image was a
256×256 PNG, left half red and right half blue.

**Answer.** HTTP 200, 375 prompt tokens: "The picture shows a red color on
the left half and a blue color on the right half." The same image in a user
message (332 prompt tokens) got the same answer.

So llama-server reads an image in a tool message, for this template and
projector. The first reading, a recorded run that went wrong because the
model saw only the sentence naming its image, is still not taken. The
criterion needs both, so decision 5 stands.
