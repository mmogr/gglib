## Process (one page)

- **Branch** `type(scope)/slug`; one conventional subject per squash-merged PR; the PR title is the subject, a lowercase declarative sentence. gglib labels: `component:`, `priority:`, `size:` (hand-picked), `type:` (`fix` for every fix). ggchat: a component label and `size/*`. Release PRs keep release-plz's names and titles.
- **No attribution lines**: no `Co-Authored-By`, `Claude-Session` or `Signed-off-by`. `Refs #N`/`Closes #N` body lines stay. Pre-push check: `git log --format=%B origin/main..HEAD | grep -ciE '^[a-z-]+-by:|^claude-session:'` prints 0. Commit author is Matt's git identity.
- **Review tiers.** Tier 1 (A3, A4, B1, C1, C2b, E1, F1, F2): two Opus reviewers, distinct lenses (correctness + the listed mutations; build/lints/platform/contracts), each in its own worktree. Tier 2 (every other code PR): one build reviewer, targeted checks only. Tier 3 (docs, comments, metadata): one source-only reviewer with the checklist plus "no fenced block removed". Reviewers are briefed on the known failure modes (greps truncated by `| head`, default-feature builds calling gated code dead, macOS builds blind to linux/windows cfg, stale trees; read other repos at `origin/main`). No push without a PASS.
- **Merges** go in twos or threes for bisectability and runner load; doc-only PRs may merge in larger batches. Stacked branches rebase with `git rebase --onto origin/main <prev>` after each squash-merge (A2→A3→A4, C2a→C2b, D1→D2, E2→E3).
- **PR body**: parity tier for gglib, what was tested, mutations tried, what is not covered, and any behaviour change named.
- **Worktrees and disk.** Before wave 1 remove every worktree whose branch is merged (`git worktree remove --force`; `git worktree prune`), record the freed and free space. Layout `~/.local/src/worktrees/<repo>/<slug>/<repo>` (ffi and ggchat leaves named `modelpipe-ffi` and `ggchat`). Author lanes, each with its own target: gglib L1 proxy (A, C2b, C3), L2 remote/axum/app-services/frontend (B1, D), L3 CLI/runtime/deps (B4, B3, B2, B5, C1, C2a, T); one gglib review lane; modelpipe one author + one review lane; ffi one author lane, reviewers source-only; ggchat one author. Reviewer lanes export `CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_INCREMENTAL=0`; measure one such lane before re-budgeting (v1 assumed 51 GiB per gglib lane; 354 GiB free). Never more than four gglib targets alive. Delete a worktree and its target the day its PR merges. `make bindings` (A3, D1, D2) is a workspace build in the author's lane.
- **Release train clicks (Matt):** mark T1 ready and merge; approve the `crates-io` environment; mark #35 ready and merge after checking its changelog lists F1, F2, T3.
