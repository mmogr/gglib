# components

<!-- module-docs:start -->

Every child of the `ChatMessagesPanel` composition root: the panel chrome around the thread (header, system prompt line, the error banner, the composer and its `[+]` menu) and the per-message rendering (a question's filled block and a reply's plain text, the fold of reasoning and tool calls, the figure and action lines under a turn, Markdown with syntax highlighting, and the context wiring message-level actions to their handlers).

## Panel chrome

| File | Role |
|------|------|
| `ChatPanelHeader.tsx` | The chat's head: the title (16/600) as the menu button for Rename · Generate title · System prompt… · Export · Start over (same prompt)… — Delete…, or the rename field; a far chat's title is plain |
| `SystemPromptLine.tsx` | Nothing for the default prompt, "Custom system prompt · Edit" for the chat's own, and the inline editor (Reset to default, Cancel, Save); owns its draft and reports only a save |
| `ChatStatusBanners.tsx` | The chat error banner. A model unloaded or crashed mid-chat has none, and no toast: `SendNoteLine` says it over the live composer |
| `ComposerFooter.tsx` | The composer: the images attached as tiles above the text, the text box ("Ask <model> anything" in a new chat, "Reply…" in a saved one once its turns are there, and nothing while they load; the bare model name, never the picker's "<model> on desk"), then one row of `[+]`, the chips that are set (the folder, `Draw ×`), the Thinking toggle (a switch labelled Thinking, neutral either way, drawn only where `useThinkingSwitch` says the model thinks), the context ring, the model, and Send (ink, ↑) which becomes Stop while a reply is written. The model is the picker on this machine's chat; plain text on the paired machine's ("<model> on desk", "desk picks the model"), and, while that machine is away (from the remote registry alone, CH-9), "desk is away since 14:02. Your message will wait." with Send disabled. Never locked: where a send has more to do than be answered, `SendNoteLine` is over it, gone while a reply is written (the reply's arrival line then says what it waits for). Paste and drop take images only where `ImageInputContext` says the model reads them |
| `SendNoteLine.tsx` | One 12 px line over the live composer saying what a send does first, in Rust's words (`components/status/sendLine`): "Qwen3-4B isn't loaded · sending loads it", "The endpoint is Off · sending turns it on", "The endpoint is Pinned to Qwen3-8B and cannot serve Qwen3-4B · sending is refused"; a crash marked failed, "Qwen3-4B stopped unexpectedly · sending loads it again", with Show log. Never a lock, a banner or a toast |
| `PlusMenu.tsx` | The composer's `[+]`: Add image…, Use a folder…, Draw a picture (▸ where there is an image model to choose) and Tools ▸, from `composerMenus`; the tool registry is read again each time it opens, so a tool registered since, built-in or MCP, is listed without opening anything else (CH-11), each named as the daemon knows it; the enabled tool servers are read each time it opens, and one whose tools the page has not read (not started) is one row for all of them (`<id>:*`), so unticking from every tool drops no enabled server; a disabled server is not offered; nothing here starts a server; which are ticked is the chat's saved choice (`hooks/useChatTools`) |
| `composerMenus.ts` | The `[+]` menu's items, pure: Add image… greyed with the model's reason (never for a model not loaded, which the send loads), Use a folder… none for a far chat and greyed for a model that calls no tools, Draw a picture greyed with the machine's reason or a submenu of the default rule and each image model (one lacking a file greyed, its title what it lacks; a choice no longer listed kept, so it can be taken back), Tools ▸ the chat's saved tools as a checklist of `toolRows` (the builtins, then each enabled server's tools or one row for all of them), "Asking gglib" or "Couldn't read the tool servers: <the daemon's words>" until the servers are read (Enable all greyed where every tool is, Disable all where none is, one box per tool, each change saved with the chat) or "This model can't call tools", and none on a far chat |
| `FolderChip.tsx` | The chat's folder (`useChatFolder`), drawn only once one is set: its name, the whole path on hover, a click to choose another, × to clear it; a warning, its title the reason, where a send was refused for it. Choosing opens the native dialog on desktop and a typed path field on web (Enter uses it, Escape leaves it; no form of its own, since it sits in the composer's, and neither key sends the drafted message), which `[+]` › Use a folder… opens too |
| `ContextRing.tsx` | The composer's ring `◔` and its detail: drawn only when the conversation has a reading (`readings/contextReading`), "Context: 2,140 of 32,768 used" on hover, the detail on a click, and from 70% the figure beside it in the warning colour, from 90% the danger colour |
| `ComposerImages.tsx` | `ImageInputContext`, which the panel gives the thread so the page's composer and every edit's read one answer (whether the model reads images, why not, its context; nothing offered without it); a composer's images as tiles above its text (thumbnail, "uploading…" or "not uploaded", "~N tokens · P% of context" on hover, × to remove), the cost against the context the ring reads and, before the conversation has a reading, against the one `ImageInputContext` gives; and `useAddImage`, the file picker Add image… opens |
| `imageCost.ts` | An image's cost as its tile says it: "~N tokens", and "P% of context" when a context size is known |
| `ModelPicker.tsx` | The composer's model ▾ on this machine's chat: Loaded (the chat's own ticked), On this Mac, and the paired machine's models while one is connected (in a new chat, each opens a new chat on that model; in a saved chat each is listed greyed, its reason "A chat stays on its machine…" said under it), then Unload <model> (every endpoint client loses it; the chat stays open) and Show <model> (its inspector, where the Log is); the choice is handed to the page, which saves it as the chat's model and starts nothing, and a refused pick is toasted in the daemon's words; plain text for a chat with another machine |

## Message rendering

| File | Role |
|------|------|
| `MessageBubbles.tsx` | A question as a filled block at full contrast, its sender above it where that was not you; a reply as plain 16 px text, its model named above it only where the reply before was another model's, the arrival line until its first token, the fold (one per reply: a reply whose tool rounds came as messages of their own, live or saved, draws one fold on its first message over all of them, `replySegments`; and, while the reply arrives, a polite live line saying each tool call as it settles), then the images its tools made, outside the fold and always shown; each turn's foot; the edit composer in the turn's place, Send for a question and Save for a reply, with a question's images, each removable, and a paste into it taking images only where the model reads them |
| `ThinkingBlock.tsx` | A reply's fold: one 12 px line, `▸ Thought for 3 s · 2 tool calls`, its time the sum of each message's (saved, else the timing tracker's), live while it thinks, open while the reply arrives and closed after unless chosen, onto the reasoning (inline code inline, CH-8) and the tool rows |
| `ToolCallRow.tsx` | One tool call in the fold: name, MCP server and state (running, its time, why it failed), opening in place onto its arguments with their Copy (while it runs too), the raw name, the result (`ToolUI`, the tool's registered renderer or the generic one) and its Copy; a running tool's progress and preview frame under the line, from `RunPreviewsContext` |
| `ReplyArrival.tsx` | A reply with no token yet: a status line with the daemon's words for its wait, verbatim ("Loading Qwen3-4B… 12 s"), else its phase; the prompt reading and its bar |
| `TurnFoot.tsx` | The line under a turn: its time on hover, a reply's figure line (`FigureLine`, the full set in its tooltip, "unfinished" in the warning colour), the action line (always in the page, faded until the turn is hovered or holds focus, always shown on the newest reply) and the branch switcher; `useTurnReveal`, hover or focus held in React |
| `TurnActions.tsx` | The 12 px text actions: a reply's Copy · Retry · Edit · ⋯ (Branch from here), a question's Copy · Edit · ⋯ (Branch from here · Delete…); Copy alone on a far chat |
| `Unanswered.tsx` | The 12 px line under a chat whose last reply did not come: "The reply failed: <reason>." from the run read here, or "Nothing answers this yet." under a question, with Retry where the chat ends in a question; not while a reply is being read |
| `BranchingContext.tsx` | What the open chat offers of its branches (its branch points, whether it ends in a question, Retry, Branch from here, and opening another chat), for the turns and rows that show it; the same object until the chat's thread is read again, so no turn draws again for a render of the page; none on a far chat |
| `BranchSwitcher.tsx` | A branch point's options: previous and next, and the count that lists each option by its line ("Nothing here yet" for a branch with nothing there), the open chat's marked; in the foot of the turn that starts the point (`TurnBranches`), and in a 12 px line after the last message where other branches go on (`BranchEnd`) |
| `MessageImages.tsx` | A user turn's images, and the strip of the images a reply's tools made: each read from the chat's store by id with the page's credential as a `blob:` URL, shown small and opened in the picture sheet on a click |
| `PictureSheet.tsx` | The one picture sheet, over the chat: any picture in the thread at fit size; the drawing tool's picture, where the chat can keep another (`MessageActionsContext.pictures`), is fixed or redrawn in it (`PictureWork`) |
| `SheetFrame.tsx` | The sheet's frame: title, the picture's size, ×, the picture and what is beside it, the footer; holds the focus and hands it back to the picture; Esc, a click outside and × close it once `mayClose` says so |
| `PictureWork.tsx` | A drawn picture in the sheet: View with Fix a part and Redo; the prompt, how much to change and Drawn with ▾ (two or more image models); Fix this part / Draw it again; while drawing the daemon's step, a 2 px bar, the frame and Stop; then Hold to see the original, Keep (a new saved picture after its source), Try again, Discard; a failure inline; closing with an unkept picture asks |
| `PictureBrush.tsx` | The brush a part is marked with: strokes in the picture's own pixels (`useBrush`), the canvas over the picture (`BrushCanvas`), and the brush row: size, Rub out, Undo, Clear (`BrushRow`) |
| `MarkdownMessageContent.tsx` | Parses and renders message text as Markdown (remark-gfm + rehype-highlight) |
| `MessageActionsContext.tsx` | React context providing the delete callback, whose chat it is, and fixing and redoing a picture to nested message components |

## Words

The composer's words that are its own, not the daemon's (state words, Loading and Loaded, Away, come from `components/status/words.ts`):

- `[+]` (named "Add to the message"): Add image…, Use a folder…, Draw a picture, Tools; "<server> · all its tools", "Asking gglib", "Couldn't read the tool servers: <the daemon's words>"; "This model can't call tools", "No tools registered", Enable all, Disable all, "Default (<model>)", "Model <id> (no longer listed)", "Missing: <roles>", and the title "Let the next message draw a picture with <model>. It applies to that message only."
- chips: `Draw ×` ("Don't draw"), the folder's name × ("Clear the folder"), "Folder path"
- Thinking (its two titles), Send, Stop, "Ask <model> anything", "Reply…"
- the ring: "Context: 2,140 of 32,768 used"
- the picker: On this Mac, "On <machine>", Unload <model>, Show <model>, "A chat stays on its machine. Start a new chat to use this model.", "Opens a new chat on <model>, on <machine>."
- the lines: Show log (after Rust's crash line), "<machine> is away since 14:02. Your message will wait."
- the arrival line where the daemon said nothing in words: "Waiting for the model" (a wait from a daemon too old to word it, or no event yet), "Reading the prompt", "Starting the reply"
- tiles: "uploading…", "not uploaded"; Tools ▸'s refusal toast: "Could not save this chat's tools: <the daemon's words>"
